# Notes

Локальная база знаний в браузере. Документы хранятся в виде Markdown-файлов
в Origin Private File System (OPFS), приложение работает как PWA и полностью
доступно офлайн после первой загрузки.

## Возможности

- Список записей с датой создания и тегами.
- Поиск по названию и по якорям: обычный текст ищет по заголовкам,
  запрос с `#` — по разделам документов. Фильтр по тегам поддерживает
  несколько тегов одновременно (AND) и прокручивается в одну строку.
- Просмотр документа с заголовком, датой создания и датой изменения
  (через `/`, если документ менялся), тегами и отрендеренным Markdown.
- Экспорт одной заметки в ZIP вместе с её вложениями.
- Импорт заметок из ZIP-архива или отдельного `.md`; импортированные
  документы помечаются иконкой (i).
- Создание и редактирование документа: заголовок, теги, содержимое и срок
  «Дата контроля» с датой и временем.
- В списке срок показывается под тегами: зелёный — ещё не наступил,
  оранжевый — уже прошёл. В заметке можно скачать событие в формате iCalendar (.ics)
  со ссылкой на документ.
- При создании новой записи из заметки можно наследовать её теги.
- Несколько тегов у одного документа: выбор чипами и добавление новых по Enter.
  Цвет тега определяется детерминированно по его тексту и не меняется после
  перезагрузки.
- Checkbox-задачи в документе обёрнуты в `label`: клик по тексту задачи
  переключает её состояние.
- Собственный Markdown-редактор:
  - жирный, курсив, подчёркивание, зачёркивание, `code`;
  - блок кода, цитата, маркированный, нумерованный и checkbox-списки;
  - горизонтальная линия, изображение, ссылка, ссылка на документ;
  - активное состояние применённого стиля и его снятие повторным нажатием;
  - продолжение маркера списка/цитаты/блока кода по Enter и удаление маркера
    повторным Enter на пустом пункте;
  - вложенные списки: Tab увеличивает уровень обычных и нумерованных
    списков с учётом ширины маркера, Shift+Tab уменьшает. На checkbox-списках
    Tab не перехватывается — работает обычная навигация по фокусу;
  - горячие клавиши `Ctrl/⌘ + B`, `Ctrl/⌘ + I`, `Ctrl/⌘ + U`, `Ctrl/⌘ + K`.
- Интерактивные checkbox-списки в режиме просмотра.
- Ссылки между документами — обычные markdown-ссылки:
  `[Название якоря (Название страницы)](/путь#якорь)`;
  для ссылки без якоря — `[Название страницы](/путь)`.
  Старый синтаксис `@{путь}[#якорь]` поддерживается и преобразуется
  в обычную ссылку при открытии документа в редакторе.
- Изображения сохраняются рядом с документом в `assets/`.
- В документе фото показывается миниатюрой; клик открывает полноразмерное
  изображение в модальном окне на весь экран. Под миниатюрой выводится
  название изображения (alt), по ширине не шире самой миниатюры.
- Синхронизация с Google Drive через Google Apps Script: SHA-256-хэши,
  пропуск неизменившихся файлов, статус в шапке.
- Экспорт всей базы в ZIP-архив.
- Все строки интерфейса вынесены в `vue-i18n` (локаль `ru`).
- Установка как PWA и офлайн-работа (service worker).
- Строка состояния PWA окрашивается в цвет светлой или тёмной темы.
- При выходе новой версии появляется уведомление с кнопкой перезагрузки.
- Иконки интерфейса хранятся отдельными SVG-файлами в `public/icons` и
  подключаются как изображения через CSS-маску с текущим цветом текста.
- Адаптивная вёрстка и тёмная тема (по системной настройке).

## Быстрый старт

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

> OPFS доступен только в защищённом контексте: `https://` или `localhost`.

### Сборка и проверка

```bash
npm run build        # проверка типов + production-сборка в dist/
npm run preview      # preview production-сборки (здесь работает service worker)
npm run lint         # ESLint, включая prettier/prettier
npm run lint:css     # Stylelint
npm run typecheck    # vue-tsc
npm run format       # Prettier: форматирование src
npm run format:check # проверка форматирования без изменений
```

Service worker и PWA-манифест генерируются только в production-сборке.
Для статического хостинга настройте SPA-fallback на `index.html`, чтобы прямые
ссылки на документы (`/<путь>`, `/<путь>/edit`) открывались без 404.

## Хранение данных

Корень базы — `navigator.storage.getDirectory()`. Данные привязаны к origin
приложения и не покидают устройство.

Новый документ создаётся в собственной директории, имя которой совпадает
с заголовком. Его публичный путь (URL и ссылки) — путь директории, а файл
называется так же, как директория:

```text
Заголовок/
├── Заголовок.md
└── assets/
    └── 1730000000-abc123-схема.png
```

URL документа: `/Заголовок`, редактирование: `/Заголовок/edit`.

`Заголовок.md` содержит YAML frontmatter и Markdown:

```md
---
created: 2026-11-24T16:12:56.000Z
updated: 2026-11-24T16:20:10.000Z
tags:
  - ремонт
---

# Заголовок

## Раздел

- [ ] задача
- [x] выполненная задача

Ссылка: [Раздел (Другой документ)](/Другой%20документ#раздел)
```

- Заголовок документа берётся из имени файла; H1 при сохранении
  добавляется автоматически.
- При переименовании заголовка переименовываются файл и собственная директория
  документа (вместе с вложенными документами и `assets`).
- Читаются и уже существующие структуры: документ может лежать в общей
  директории (`Отопление/Заметки.md`), путь вложенных документов поддерживается.
- У документа может быть несколько тегов. Теги выбираются кликом по чипам:
  повторный клик снимает тег. Новый тег вводится в поле и добавляется по Enter.
  Нативные checkbox остаются для доступности. Цвет чипа детерминированно
  зависит от текста тега: нейтральный оттенок, яркая обводка и текст,
  приглушённый фон; в тёмной теме оттенки адаптируются.
- Markdown-рендер проходит через DOMPurify; HTML из документов безопасен.

### Ссылки на документы

```md
[FABIA](/FABIA)
[Блок предохранителей и реле (FABIA)](/FABIA/Блок%20предохранителей%20и%20реле)
[Общая информация (FABIA)](/FABIA#общая-информация)
[Соседний документ](/Соседний%20документ)
```

Публичный путь документа — это путь его директории (у документа, созданного
в приложении, — `/Заголовок`). В редакторе старые ссылки `@{путь}[#якорь]`
преобразуются в такой обычный markdown-формат; при сохранении он остаётся
в файле. Якорь — slug заголовка раздела (кириллица сохраняется) или сам текст
заголовка.

### Синхронизация с Google Drive

Скрипт для Google Apps Script и инструкция по развёртыванию лежат в
[`.sync-services/drive`](.sync-services/drive/README.md).

Подключение:

1. Разверните Apps Script Web App по инструкции.
2. В приложении откройте меню «⋯» в шапке → «Ввести токен доступа».
3. Укажите URL Web App и токен `SYNC_TOKEN`.

Токен также можно привязать ссылкой:

```text
https://your-notes.example/?drive_token=TOKEN&drive_url=https://script.google.com/macros/s/.../exec
```

После загрузки приложения токен сохраняется в браузере и удаляется из URL.
Если URL Web App постоянный, его можно задать при сборке через
`VITE_DRIVE_SYNC_URL`; тогда достаточно одного `drive_token`.
Для каждого файла считается SHA-256: если хэш на сервере совпадает, файл
повторно не отправляется. Файлы больше 8 МБ пропускаются. Удаления не
синхронизируются; при конфликте побеждает более новая версия.

### ZIP

Кнопка «Экспорт ZIP» в меню «⋯» собирает все файлы хранилища, включая
изображения, в архив `notes-ГГГГ-ММ-ДД.zip`.

### Одна заметка: экспорт и импорт

- В просмотре заметки кнопка «Экспорт» скачивает ZIP с markdown-файлом и
  вложениями из `assets/`.
- В меню «⋯» → «Импорт ZIP или MD» можно выбрать один или несколько файлов.
  ZIP сохраняет структуру папок; одиночный `.md` получает собственную папку.
- Если во frontmatter нет `created`, дата берётся из метаданных ZIP-записи или
  `File.lastModified`. Если даты нет и там, дата создания не выводится.
- Импортированные документы помечаются голубой иконкой (i) слева от заголовка.
  После первого сохранения или изменения документа иконка исчезает.
- Если заметка менялась после создания, в строке даты показывается
  `дата создания / дата изменения`.

## Локализация

Все тексты интерфейса находятся в
[`src/shared/i18n/messages/ru.ts`](src/shared/i18n/messages/ru.ts).
Конфигурация — в [`src/shared/i18n/index.ts`](src/shared/i18n/index.ts):
локаль `ru`, fallback `ru`, Composition API. Компоненты используют
`useI18n()`, а код вне Vue — помощники `translate()` и `translatePlural()`.

`document.title`, `meta description` и `lang` документа также задаются
из i18n при запуске приложения. Для нового языка добавьте файл сообщений
и зарегистрируйте его в `messages` в `src/shared/i18n/index.ts`.

## Архитектура

Проект следует Feature-Sliced Design:

```text
src/
├── app/           # корневой компонент, router, глобальные стили
├── pages/         # notes-list, note-view, note-edit
├── widgets/       # app-header, note-content, markdown-editor
├── features/      # export-archive, export-note, import-note,
│                  # insert-image, insert-link, insert-document-link,
│                  # search-notes, sync-drive
├── entities/      # note: типы, OPFS-репозиторий, Pinia-store, ui
└── shared/        # ui, lib (markdown, frontmatter, slug, даты),
                   # i18n, urls
```

- Vue 3 (`<script setup>`), TypeScript, Vite.
- `vue-router` (History API), `pinia`.
- `marked` + `dompurify` для рендера, `jszip` для экспорта, `yaml` для frontmatter.
- `vue-i18n` для локализации интерфейса.
- ESLint (TypeScript + Vue), Stylelint, `vue-tsc`, `vite-plugin-pwa`.

## Поддерживаемые браузеры

Актуальные Chrome, Edge, Firefox и Safari. Нужна поддержка OPFS и service worker.
Светлая и тёмная темы выбираются автоматически. Для установки PWA на iOS
используйте меню браузера → «На экран „Домой“»; установка доступна и через меню
браузера.

## Стиль кода

Правила проекта собраны в skill
[`code-style`](../.agents/skills/code-style/SKILL.md):

- TypeScript следует [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html);
- `v-if`, `v-else-if`, `v-else` и `v-for` размещаются только на `<template>`;
- вычисления выносятся в `computed`, разметка содержит простые значения;
- порядок блоков SFC: `<template>` → `<script setup>` → `<style>`.

ESLint использует GTS-совместимый набор правил (`no-floating-promises`,
`block-scoped-var`, `prefer-arrow-callback`, `curly`, `eqeqeq` и другие).
Форматирование проверяется через `prettier/prettier` с настройками GTS:
одинарные кавычки, `bracketSpacing: false`, `trailingComma: all`,
`arrowParens: avoid`. Порядок блоков SFC проверяется `vue/block-order`.

## Публикация на GitHub Pages

Публикация выполняется автоматически через GitHub Actions при push в `main`
или вручную через **Actions → Deploy GitHub Pages → Run workflow**.

Адрес приложения:

```text
https://<username>.github.io/notes/
```

В GitHub включите Pages:

**Settings → Pages → Build and deployment → Source: GitHub Actions**.

Workflow [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml):

- собирает приложение с base path `/notes/`;
- копирует `dist/index.html` в `dist/404.html`, чтобы прямые ссылки на
  заметки работали на GitHub Pages;
- загружает `dist` как Pages artifact и публикует его.

Если репозиторий называется иначе, измените `BASE_PATH` в workflow.
